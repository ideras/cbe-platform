# Security checklist of workspace exams

Phase 8, task 3. For each check of the plan: what it says, what verifies it (a test that runs, not a statement), and what the last run said. A check is as
good as its test; where a test is weaker than the check, this says so under **Limits**. The tests that need the container host are `cbe-portalctl image test` (which replaced `images/test.sh`, decision D-CB-10),
`deploy/workspace/test-security.sh` (the runner and a real container), `test-grading.sh`, `test-image.sh` and `test-server.sh` (`deployment.md`); the rest run in CI.

The threat is a **student who is a programmer with a shell** in a container, an hour, and every reason to look: they can run any program in the container's
limits, write any file under `/work`, say anything on the agent's socket (the agent runs as them), and send anything over their WebSocket.

| # | Check | How it is verified | Result |
|---|---|---|---|
| 1 | **No network from a student's or a grading container** | The container is made with `--network none` by one function (`hardened`, `internal/runner/policy.go`) that student, grading and verification containers share (`TestAGradingContainerIsHardenedLikeAStudentsAndHasOnlyTheTwoMounts`; `dockerrt`'s `TestTheDockerTranslationKeepsTheHardening`). | 2 | **No path escapes `/work`** (symbolic links, `..`, hard links, `/proc/self/root`) | The agent opens every path with `openat2(RESOLVE_BENEATH)`, and the relay and the agent's decoder refuse `..`, absolute paths and control characters (`agentproto.CheckPath`). Fuzzed: `FuzzCheckPath` and `FuzzDecodeRequest` (about 28 million inputs), `FuzzFilePaths` (every file operation on made-up paths, with links in `/work` to a folder outside it: nothing outside is read, changed or added to: 1.9 million inputs). **In a real container** (`TestRealRunner`, "nothing leads out of /work"): the student makes links to `/etc/passwd`, to `/proc/self/root`, to `/proc/1/root`, to `/`, upwards, to the agent's folder, and a hard link to a file of the image (which is on another file system and is not made); every read through them is refused, a write to `../x`, `/etc/passwd` or `a/../../x` is refused, and the **archive that the snapshot reads** has the links as links and the content of nothing outside `/work`. ## Limits (said, not fixed)

- **A student's program can read `/grading` while it is being graded** (it runs in the container `grade` runs in). Grading measures; it is not a lock (P6-13). The hidden tests are never in a student's container *during the exam*.
- **The history is built from the agent's replies.** The agent is the container's PID 1 and the same user as the student's programs. The server treats everything it says as hostile (decoded, limited and encoded again, which the hostile-agent target checks), but it does not treat a reply as proof of the files: **the files come from the archive of the container's disk** (snapshots, D14), not from what the agent says. Whether a student could make their own agent say something false in the history by tampering with a process of the same user was not tried.
- **The Containerfile of an exam is the proctor's own** (P7-12): its build has the host's network and runs as root in the build container.
- **A setuid file a build adds** is not looked for (the student's container has no capabilities and no new privileges, which makes it harmless).
- **The checks above that need a host** ran on one: rootless Podman on this machine (Podman 4.9, kernel 7.0). A different runtime or kernel has to run `cbe-portalctl image test` and `test-security.sh` again.
- **The router** (Wi-Fi isolation, who can reach the exam server's port) is the owner's network and not this code's.
