## What the work found

1. **A build that is cancelled leaves a container behind, and nothing in the Docker API shows it.** The real test reported `cpp20-working-container` left after a build that timed out. Podman 4.9 leaves the stopped container of the step it cancelled; the compatible API neither lists nor inspects it, but a **forced delete by name works** (tried by hand first). The runner removes `<image>-working-container` and `-1`, `-2`… after a cancelled build and when it starts (P7-13); a build that ends any other way leaves nothing (tested for each way, on the real runtime and with the fake).
2. **The proctor's application could not import a workspace package at all.** The plan's architecture lists "package import" for it, but no phase built it, and the only callers of the import route were the tests and the manual-test script. Phase 7 makes the build "a proctor action before publishing" with its log "in the proctor app", so it needed an exam to act on: the import is built here (P7-1). It is the part of this phase to look at first.
3. **`RUN --network=host` works in a build** on this host (the build joins the host's network: a Containerfile could reach the services on its loopback), **and an absolute bind source does not reach the host** (`--mount=type=bind,source=/etc` resolves inside the build's context, and `..` is held at its root). So the first is refused and the second is not a hole (P7-4).
4. **The course image has no certificates and no apt sources** (by its own contract), so a teacher who copies "`apt-get install` over HTTPS" gets a build that cannot trust the archive. The build lends the server's certificate bundle as `ca.crt` (P7-6), and `images.md` has the step that was built for real.
5. **The log buffer I first wrote was quadratic:** every write past the limit copied the whole tail, so a 3 MB build log took 20 s under the race detector. It is a ring buffer now (0.05 s), with a test that reads it back in order across many wraps.
6. **A flaky test that was already there:** the proctor dashboard's tests failed about one run in six under `-race` (also on the Phase 6 commit, found by running it there): 27 tests set the fake server's reply hook without a lock while the polling goroutine read it. It is set under the lock now (P7-17), and ten runs in a row pass.
7. **The build's memory limit is enforced** by this runtime (a step that goes over is killed with exit 137), unlike the "killed for memory" flag that `container inspect` does not reliably set (Phase 6).

## Deviations from the plan, and conflicts found (standing rule 1)

1. **Package import in the proctor application** (above): not in any phase, built here (P7-1).
2. **Every `FROM` must name the exam's course image or an earlier stage**, where the plan says the *first* `FROM` must be an approved course image (P7-3). Stricter, so a later stage cannot pull an unpinned image; and the exam's `image:` and the `FROM` must agree.
3. **`image.build` takes the approved image and a `rebuild` flag, and answers whatever way the build ended** (the plan's Appendix E: "exam ID, Containerfile, build context"), as `grading.run` does (P7-6). Appendix E is updated.
4. **The base is pinned by the build, or its written digest is compared**, rather than refusing a `FROM` with no digest (the plan: "by digest, or the build pins it and records it").
5. **Verification is more than the entrypoint and the user** (layers, command, working folder, the agent's label, the agent's hash in a container with no network), because the entrypoint alone is satisfied by a `COPY` over the agent (P7-8).
6. **Images are not removed** when an exam is deleted or built again: Appendix E has no `image.remove`, and adding an operation is a change to what the runner accepts (Phase 8's checklist). `images.md` says how to remove them (P7-12).
7. **The log is read when the build ends, not while it runs:** the runner answers once (P7-10). A live log needs the runner to stream or to keep a file.
8. **A setuid file a build adds is not looked for** (P7-12): the student's container has no capabilities and no new privileges.

- **One real build over HTTPS** (`nlohmann-json3-dev`), once. Other packages, other archives and other architectures were not tried.
- **Podman 5.x and rootful Docker** were not tried. A newer Podman may not leave the cancelled build's container; the runner's cleanup tolerates both (a name that is not there is not an error).
- **A large context** (the limit is 22 MiB) and **a build of many minutes** were not run for real; the timeout and the memory limit were, at small sizes.
- **A student who is working when the image is rebuilt** keeps the container they have, and a student who logs in after gets the new image; the exam is then mixed. The dialog does not warn about it (the server does not tell it how many students have started).
