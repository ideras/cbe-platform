# CI verification status

The workflow in `.github/workflows/ci.yml` builds the three applications on six native runner labels, checks the output architectures, and prepares the fifteen application archives named in the deployment guide. macOS slices are combined within the same workflow run; the final universal server has a separate smoke job for each macOS architecture. Artifacts are uploaded before all tests complete, so their presence does not imply a passing job. The macOS bundles are ad-hoc signed, use CI identifiers and are not notarized.

Local Linux x64 verification passed the pinned Go 1.26.8 build, Go vet and race tests in all six modules with the built-server integrations, both frontend unit suites, both Playwright suites (73 student and 125 proctor tests), archive architecture and checksum checks, and server health. The Windows desktop applications have also been cross-compiled as PE x64/ARM64, which does not verify native execution. See the workflow run for actual hosted job and artifact results; no Windows, macOS or ARM64 hosted result is assumed here.

The first hosted run reported successful Linux x64 and ARM64 jobs. Both macOS jobs failed at the thin-binary `lipo` check because the input filename followed `-verify_arch`; the checks were corrected to put the input first and require another hosted run. Both Windows jobs reported test failures; their detailed logs are needed to identify all causes.

In [run 40724847477](https://github.com/ideras/cbe-platform/actions/runs/40724847477), Linux x64 and ARM64 passed and produced all six Linux archives. Windows built all six executables but failed packaging, frontend tests, server startup and Go tests. macOS x64 built and uploaded its thin binaries but failed a disconnect test; macOS ARM64 was cancelled before a runner was assigned, so universal packaging could not download its slice.

In the follow-up [run 40734674992](https://github.com/ideras/cbe-platform/actions/runs/40734674992), both Linux and both macOS native jobs passed, and universal packaging succeeded. Windows x64 and ARM64 produced all six archives and passed frontend tests; both failed server smoke and Go tests. Windows storage and exam-document tests now pass after correcting drive-path URLs and checkout line endings. Further fixes to platform-specific fixture assertions have been prepared. Windows credential protection and a timing-sensitive ARM64 monitoring test remain unresolved. The universal smoke jobs were skipped because the Windows matrix failed; their condition has been corrected and needs hosted verification.

The Windows server now checks the token file's ACL instead of Unix mode bits. CI creates a restricted temporary directory and checks private and publicly readable files. This change requires passing native Windows builds and tests before Windows server artifacts can be treated as deployable. Linux and macOS retain the existing private-file protection.

The three previously failing jobs were then traced to two causes. The proctor dashboard's disconnect test parked an HTTP handler on a channel send nobody drained after the test body finished; the poll loop's post-connection requests filled the buffer, the parked handler kept an active connection, and the cleanup's `server.Close` waited until the 20-minute timeout on the slower ARM64 runners. The handler now counts requests without ever blocking and always answers once the test releases it. Windows ARM64 rejected test and helper token files whose DACL only inherited the surrounding directory's ACL (Windows 11 profiles grant application-container SIDs, which the strict credential policy rejects). Every test and script that creates a private input — the Go config, server and student-client integration fixtures, and the Python manual-exam, smoke and ACL-test helpers — now replaces the inherited ACL with an explicit private one (`icacls /inheritance:r /grant:r *<current sid>:F`), so the policy holds regardless of the runner image's temporary-directory inheritance. The manual-exam helper now also prints the failing phase and the bootstrap log on Windows instead of a generic message, so any remaining hosted failure is diagnosable. Local Linux x64 verification after these changes passed all six modules, the built-server integrations including the manual-exam workflow, and the smoke check; Windows and ARM64 behavior needs a hosted run to confirm.

Go vet and tests cover all six modules, including desktop integration against the built server and the synthetic regression output. Race tests run except on Windows ARM64. Frontend unit tests run per platform; Chromium browser tests run on Linux x64. Audio device mutation, interactive screen-recording consent and multi-monitor capture remain manual checks. No CI signing, deployment, or publication secrets are required.
